# The Marfa's half of Settings

Status: Overview, Account, Apps, Keys, Addresses, Types, Sources, Recently Deleted, History, File Storage, Connectors, Webhooks, Folders, Backups, Updates, Housekeeping, Activity, Monitoring, Limits and Start-Up are built. Folders only reads.

Where it lives: `MarfaSettingsPage`, `MarfaSettingsHost`, `OwnerCalls`, `ClientOwnerCalls`, `AccountModel`, `AppsModel`, `KeysModel`, `AddressesModel`, `OverviewModel`, `ServerHealthModel`, `BackupsModel`, `UpdatesModel`, `HousekeepingModel`, `WebhooksModel`, `ConnectorsModel`, `FoldersModel`, `SourcesModel`, `SourceLimitModel`, `FileStorageModel`, `InstanceSettingsModel`, `OwnerDrafts`, `OwnerPermissions`, `OwnIdentity`, `OverviewPage`, `AttentionConcern`, `AccountPage`, `AppsPage`, `KeysPage`, `AddressesPage`, `TypesModel`, `TypesPage`, `TypeCalls`, `ServerTypeCalls`, `SourcesPage`, `RecentlyDeletedPage`, `HistoryPage`, `FileStoragePage`, `ConnectorsPage`, `ConnectorHealth`, `ConnectorWording`, `WebSignInSheet`, `WebhooksPage`, `FoldersPage`, `BackupsPage`, `UpdatesPage`, `HousekeepingPage`, `InstanceCalls`, `ClientInstanceCalls`, `StoredSettings`, `ActivityModel`, `ActivityPage`, `MonitoringModel`, `MonitoringPage`, `LimitsModel`, `LimitsPage` and `StartUpPage` under `MAPP/Settings/Marfa/`.

The Marfa's pages show and change what the server holds, as the owner. They stand alone: they reach only the parts and the host protocol ([Agreed designs](agreed-designs.md#settings), `MAPP/Settings/Marfa/AGENTS.md`). Every call needs the server and is never queued. A page opens only when the sign-in holds its permission, and when it does not, Needs a Permission says in the page's own words what MAPP isn't allowed to do there (`MarfaSettingsPage.permissionLine`, one line for each page, never shared); the server's answer wins over what MAPP thinks it holds, so a call refused with `403 forbidden` names the permission the server says is missing, and the grants are read again. A read or write refused that way shows Allow More… in its problem row (`OwnerProblemRow`), and the row names what MAPP isn't allowed to do in the page's own words where the server names the page's permission.

## What each page does

| Page | Permission to open | What it holds |
| --- | --- | --- |
| Overview | `instance.read` | The Marfa's head card, what needs attention, its name and release, and how it stands. A part the sign-in may not read is left out. |
| Account | none | The owner's username and email as the server holds them (read only), Change Password…, the passkeys (Rename, Remove, Add a Passkey…, which opens the server's own page) and the browsers signed in (Sign Out). |
| Apps | `grants.manage` | The connected apps. An app's page holds its access by type, which can only be narrowed, one row for its owner permissions (the same part as a key's), the keys it made, the data it keeps with Remove… (item counts by state, never a size) and Disconnect, whose alert has Also remove its data, off by default. |
| Keys | `keys.manage` | The owner's keys and the keys apps made. A key's page holds its expiry with Extend… (which gives the same key a later end, or none), its tier, its source (set once, shown with a lock), its access by type (narrowing only), one row for its owner permissions and Revoke. New Key… needs `keys.mint`. |
| Addresses | `config.manage` | The sign-in address, the other addresses and the websites allowed to call the server. |
| Types | `schema.write` | The types the server lists, in Yours (types the owner made), From Plugins (each with its plugin) and Built In, each with its items and what it is based on, and New Type…. A type opens a page of its own. The owner's type holds its name, plural, icon, base (Based On), description (200), guidance and statuses by group: the words a parent gives are locked, the type's own are chips with a plus that adds a word in place, and a word's meaning (120) is in its menu. A plugin's or Marfa's type is not editable: it offers New Child Type… and its icon, and says where it comes from. Guidance, with the guidance of the types above it, is shown and never written here. |
| Sources | `keys.manage` | The sources that hold items, each with its name and mark, which can be renamed or given another mark for every app, and Limit Sources, which needs `config.manage` as well. |
| Recently Deleted | `items.purge` | What the server holds in its bin, Restore on each row and Empty, and how long items wait (needs `config.manage` as well). Show All opens every deleted item as a table page: a checkbox column, the count of those selected in the foot, and Permanently Delete… and Restore for the selection. |
| History | `config.manage` | How long and how many versions of an item the server keeps, and how long it keeps its logs. |
| File Storage | `config.manage` | Where files are kept, how many copies, the free space kept, reading text in files, fetching files from the web and removing files nothing uses. |
| Connectors | `connectors.manage` | Each installed plugin's connector with how it stands and which machine runs it. A connector's page holds Run Now, Status, Pause, Runs On, Sign In… (only for a connector whose plugin declares a vendor sign-in), its Settings (a secret shown only as Set or Not Set) and What It Brings. |
| Webhooks | `webhooks.manage` | Every webhook the server lists for this sign-in, grouped by who made it: MAPP's own first, then each app and key by name, a key that expired or is gone and an app no longer connected last. A webhook MAPP made has a page with its address, what it is for (a type or every type), Sending, the events it sends (All Events and one each), its deliveries with Redeliver on every row, and Delete. Another maker's page shows the same read only, with its deliveries and Delete. New Webhook… is a sheet. |
| Folders | none: a folder is read as an item, under the access MAPP holds to every type | The synced folders the server lists, each with the copies that keep it (named by the sign-in that reports them), how each stands and what needs attention. |
| Backups | `backups.manage` | Where the server keeps its backups (a folder on the machine it runs on) and how often it takes one, which need `config.manage` as well, Last Backup with Back Up Now, and the backups with Restore… on every row. Show All opens every backup as a page, where one can be chosen and restored. A restore asks first, needs a recent sign-in and adds what the backup holds without changing items already here. |
| Updates | `instance.read` | The release the server runs, Check for Updates beside Update where a newer one is ready (Update needs `instance.maintain`), the steps while it updates, Check Automatically (needs `config.manage`) and how the last update ended. Where the server cannot update itself it says how, with Copy Steps. |
| Housekeeping | `instance.read` | The jobs the server runs by itself with how often, when each last ran and how it went, and the clock hold with Confirm Date… (needs `instance.maintain`). |
| Activity | `audit.read` | The audit log as a table that is a page of its own, newest first, a page at a time, with a filter by kind (Access, Items, Settings, Housekeeping) and a search. |
| Monitoring | `config.manage` | The heartbeat, the error reports and the telemetry the server sends: a switch each, and the addresses and tokens they use, shown only as Set or Not Set. |
| Limits | `config.manage` | The limits the server lets the owner change, each a number with its unit inside: request sizes, rate limits, file reading, connector deliveries, live-update viewers and fetching files. |
| Start-Up | `instance.read` | What the server started with, read only: each setting's name, what it does and whether it is set, never its value. |

## Rules

- **`sign_ins.manage` is asked for from Account, never at sign-in.** The first time the owner chooses Change Password, or Allow More… beside the sign-ins or on Connection, MAPP asks for it. Cancelled, or approved without it, nothing opens and the page says so.
- **A password is never kept.** It lives in the sheet's fields until the call ends, is never logged, and is cleared on success, on Cancel and when the sheet closes. A wrong current password keeps both fields with the red ring and one line.
- **Narrowing asks first, and only narrows.** An app's access is sent with the access it was read as; a change made elsewhere is told as a conflict, the page reads again and nothing is changed. A key's access is sent with `narrow_only`, and narrowing a key or removing one of its permissions names the change and says it can't be undone. Narrowing a grant that holds only a write to Read Only sends a read in its place, never nothing. Disconnecting an app deletes its webhooks and leaves the keys it made working (`keys-and-oauth/grant-revoke-keeps-keys`, `events/webhook-grant-revoked`). Signing a browser out asks first, naming the browser.
- **An app's data is counted, removed for good and never half-told.** Each `app.<vendor>` namespace the app's grant names is read with `GET /app-vendors/{vendor}/data` (`grants.manage`): items by state, no byte size, since Marfa answers counts. Remove… asks first, says it deletes for good, the items in the trash too, and that only a backup brings it back, then repeats the call as the package does until none is left. A removal that stops with items left says how many were removed and that some may be left, with why it stopped, and shows the counts read again (or, where that read fails, says MAPP couldn't read what is left); once any item has gone it never says nothing was changed, and never "done". Disconnect's checkbox sends `remove_data` in the write that disconnects; above 1,000 items the server refuses that, so the data is removed first and the app is disconnected only once none is left. If the disconnect then fails, the page reads the data again and says it was removed and the app is still connected, not that nothing changed. MAPP's own namespace (`app.mapp`, which holds `app.mapp.preferences`) is shown and never removed or offered in the checkbox here: removing it is Connection's Remove… (and its Disconnect checkbox), which stops `PreferencesSync` first, where a purge from this page would delete the item under it.
- **Only something read before it changed is "changed somewhere else".** That is a grant, a stored setting, or another Marfa now answering at the address (`instance_changed`). A `409` that the server words itself (the sign-in address refusals, a new key's source held by another key) shows the server's words, the source's on the Source field.
- **A key is shown once.** The sheet that follows New Key holds the plaintext; closing it drops it. Copy marks the clipboard concealed and clears it after a minute if nothing else was copied.
- **An address is checked before it is written.** The server's `POST /config/address-check` says what adding, removing or moving would do, and an answer holds only for the address typed when it was asked: typing again drops it until the new address is checked. Moving the sign-in address shows the consequences in the sheet and writes exactly what was checked; the server asks for a recent sign-in, which the package shows in place. Every write names the instance that was read.
- **A draft is handed back when Settings closes or the app quits.** The address typed in Addresses and New Key's name and source go through `Notices.notKept`, as This Marfa's draft does (`OwnerDrafts`). A password is never kept, and a key's secret is never handed over: if the window closes while a new key is shown, MAPP says the key was made and its secret can't be shown again, so it can be revoked on the Keys page if it wasn't copied.
- **Owner permissions are counted, never all or nothing.** A key's page and an app's page each show one row (`OwnerPermissionsRow`), Look After This Marfa, with "None" or "3 of 14". With some held it opens a page of its own (pushed, Back returns) with one switch each; a switch can only be turned off, and turning it off asks first. New Key shows the same row with Choose…, which turns the sheet to a page of switches and back.
- **A sheet is shown by the window.** A page hands its sheet to `SettingsSheetPresenter` (`settingsSheet(presenting:)`), which draws it in the middle of the whole window, not under the toolbar; what it shows is read from the page's model. A sheet grows with what it holds up to the window's height, then its content scrolls between its title and its buttons. A field's placeholder says something its label does not (the address field's "https://"), never the label again.
- **The server's own settings are sent at once, one page at a time.** History, File Storage, Recently Deleted's wait and the Overview's name are `InstanceSettingsModel` settings, sent by `PATCH /config` with only the setting changed and the instance read. A pop-up or switch sends when it changes; a number or the name sends on Return or when the field is left. A page saves only the settings it shows, so what another page holds typed is not sent by it. A setting the server does not hold shows the value the server documents as its default in the pop-up ("30 Days"); the menu's item for the default reads "Default (30 Days)" and removes the setting.
- **Keeping things for less time asks first.** A retention that is shorter than the one the server holds (or may be, where the server holds none MAPP can read) asks, names what it removes and says it can't be recovered. Keeping things as they were puts the pop-up back. Zero days is no limit where the contract says so (deleted items, activity, events, table changes and connector deliveries) and an empty window for versions. Keep Free on Disk asks the same way when it is lowered, naming the new and old values, since a number typed on the way to a larger one is sent when the field is left. A question still open is dropped by Revert and by closing Settings, a second save waits until it is answered, and a change already agreed to is not reported as left unsaved when Settings closes.
- **One reader of the server's health.** `Server.health()` in the package (`GET /health`: the open fields for any sign-in, the detail for one holding `instance.read`) is read once by `ServerHealthModel`, which the host holds, and Overview, Backups and Housekeeping all read it. A part is Working, Needs Attention or Not Working from its own status (Database is the worse of its read and its write), never from a concern's title. Where health could not be read, Database, Disk, Files and Backups say Couldn’t Check, never Working. The server's own `error` and `lastError` texts are never shown: each page words a title and one plain line from what the server counts (`UpkeepWording`).
- **Overview reads what the package offers.** Needs Attention is `GET /attention`. Each concern shows the server's title and one plain line MAPP words from its kind and reference (`AttentionConcern.shownLine`), never the server's own message, which names settings by key and requests by path; where MAPP has no wording, the title alone. A concern MAPP cannot place stays under Needs Attention. A development build reports version 0.0.0, which is no version, so its Marfa row is left out and only an update line shows. The Database and Files sizes come from `GET /metrics`. The server does not give free disk space, so Disk says Working or what the server says is wrong. Backups is a link to the Backups page where the sign-in may manage backups, and a ready release links to Updates, which carries a badge of one.
- **Needs Attention shows only the action that exists.** A concern opens the page that looks after it where the sign-in may open that page: a key concern Show Keys, a backup concern Show Backups, a job or clock concern Show Housekeeping, a folder concern Show Folders and a secret Monitoring holds Show Monitoring. The others (health, connector, fault and unavailable) say what is wrong and offer nothing until their pages exist. A setting MAPP has no name for is titled "Set a Secret Again", never by its key. MAPP's own row, "MAPP Can Look After Part of <Marfa>", with Allow More…, comes first while fewer than all the owner permissions are held. The sidebar's badge counts the server's concerns only.
- **Sources are written to the server for every app.** A rename or mark needs the server and is never queued; a refusal keeps what was typed in the sheet. Limit Sources is the server's source filter (`enforcement.source_filter`): written whole with the other two levers as they were read, so a change made elsewhere before the write is told and not written over; the contract gives a config write no version, so a change in the moment between the read and the write is not caught. Another Marfa answering at the address is told in the settings page's words, and the draft starts again from it. Types are checked, then sources; a limit that names types and no source waits, since it would hide every item of those types from every app.
- **Stored settings are written after a fresh read.** Monitoring and Limits send a change only once a read of `GET /config/settings` finds each setting it changes as the page showed it, and name the instance that was read; a setting changed elsewhere is told in a notice that names it ("Changed Elsewhere": "<Setting> was changed elsewhere. MAPP read the new value; yours wasn't saved."), the page shows what is there now and nothing is written over it, and the notice closes when the person next edits or chooses Close. A write the server answers as a conflict is told the same way. Another Marfa answering at the address is told as that, in one line under the setting (the sentence Overview uses), and nothing of it is adopted: the page keeps what it showed and sends no retry to it. A write that arrives while another runs waits for it. If the read after a successful write fails, the page keeps the values it sent, so a later write is not told it changed elsewhere.
- **A limit is checked before it is sent.** Each limit has the contract's range, in what the server holds; sizes are shown in megabytes (1 MB is 1,048,576 bytes) with thousands separated, and numbers are grouped, pointed and parsed as the Mac's region writes them (a separator the region does not use is refused, never guessed at). A value out of range, or not a number, stays in its field with the red ring and one line, and nothing is sent. A field emptied removes the stored value, so the server's default applies. A value is sent when the field is left or Return is pressed.
- **A secret is only Set or Not Set.** The server never returns one. It is changed by typing it again, in a sheet with a secure field that is never handed over and is dropped when the sheet closes (a setting the server lists as not secret is a plain field). Remove… is in the row's menu and asks first, saying what stops. The PostHog host and the project token are set together, as the server requires (one typed alone is told before anything is sent), and removed together. Turning the heartbeat or the error reports on is refused in one line while nothing receives them, before anything is sent.
- **The audit log is paged by cursor.** The server gives no count and no way back, so the page says which entries it shows ("1 to 20") and keeps where each page began for Newer; Newer and Older appear only where there is another page, and a read that fails for a new filter shows no rows of the old one. They are text buttons because text says more than chevrons. An action is put into MAPP's words; one the contract does not name is put into words from its own name.
- **No server wording shown as it is.** A server's refusal is shown only where it holds no setting name, code or route; otherwise one plain line says nothing was changed.
- **A connector's health is derived, in this order.** The server gives no health word, so `ConnectorHealth.of` takes the first that holds, from `GET /plugins/{name}/connector` (`paused`, `host`, `registration`, `run_requested_at`), `GET /connectors/{registration}` (`last_heartbeat_at`, `last_run`, `problems`), the host's `last_seen_at` (`GET /connector-hosts`) and the settings' `missing`: **Paused** (the owner paused it); **Needs setup** (a required setting has no value, named in the page's line); **No machine** (no host); **Waiting to start** (a host, but no registration yet: the line says whether the machine has been seen); **Not heard from** (the latest of the heartbeat, the last run's end and the machine's last visit is over an hour old); **N problems** (the connector reports problems of its own, which the page lists under Needs Attention as it wrote them); **Last run failed**; **Run requested** (Run Now was asked and the connector has not yet reported a run for it); **Ran <time ago>**; **Hasn't run yet**. A connector whose control could not be read, or whose registration it names but could not be read, is "Couldn't read", never "Waiting to start". Green is Ran, orange is any word that needs the owner, grey the rest.
- **Pause, Resume and Run Now are stored choices.** The server keeps them and the connector follows them at its next run, which the page says under Running; MAPP never starts a run. Run Now is refused while paused (`409 connector_paused`) and the page shows the server's line, which holds only the plugin's name. While a run is asked for, the open page reads the connector again every five seconds, up to ninety seconds. "Run requested" ends when the connector reports the run (`run_requested_at` clears then, not when the connector takes the request), so a run that lasts longer than ninety seconds keeps "Run requested" until the page is read again.
- **A connector's settings come from the server, as it declares them.** A label is shown in title case whatever the plugin wrote; a switch, a pop-up, a text or number field sends when it changes or the field is left, and an empty field takes the value away so the default applies; a refusal keeps what was typed and is handed back when Settings closes. A required setting with no value shows "Needed before it can run." A connector with a vendor sign-in does not show the setting that sign-in sets.
- **A connector's secret is only Set or Not Set.** It is set or changed in a sheet with a secure, one-line field that is never handed over, held in a draft or given to the accessibility tree, and dropped when the sheet closes; Remove… in the row's menu asks first and sends `null`. A secret the server cannot read (the Marfa was restored or moved) says so and is set again. The field is one line: a setting's `kind` is `text` for every secret, so a bundle cannot say that a secret (GitHub's private key) holds several lines, and MAPP does not guess from a name. `marfa plugins secret` sets it from standard input.
- **Which machine runs a connector is chosen from the linked machines** (`PUT /plugins/{name}/connector`). There is no "No Machine" choice to move one off its machine: the package's call cannot send `{"host": null}` (withmarfa/marfa-swift#545). Where no machine is linked, the row says so; linking one is not a page here.
- **A vendor sign-in goes through the Marfa.** Only a connector whose plugin declares `sign_in` shows Sign In…. MAPP starts it with `return_to` set to its own registered redirect (the server accepts that only from the app that registered it), shows `url` in the system's web authentication sheet (`WebSignInSheet`) and then reads `GET .../sign-in` for `status` and `reason`. A sign-in that cannot start because the client settings are not set (`409 connector_sign_in_settings_missing`) says "Set <labels> first."; a failure is put into MAPP's words from the one outcome word and never shows the provider's text; a sign-in started by a key, not an app, is refused by the server and says MAPP needs to be signed in as an app. "Signed In" is the sign-in's token setting holding a value.
- **What It Brings is read from the plugin's bundle** (`connector.kinds`): each kind with the type it is written as and which way it moves. It is not a mapping screen, which is another page.
- **A webhook's signing secret is shown once.** The sheet that follows New Webhook holds it, and closing the sheet drops it. Copy marks the clipboard concealed and clears it after a minute if nothing else was copied (`OwnerClipboard`, which a key's secret uses too). If the window closes while it shows, MAPP says which webhook was made and that its secret can't be shown again, so the webhook can be deleted and made again. The page reads back only the last four characters.
- **A page shows its list before the rest is read.** Webhooks and Folders show the list as soon as it is read, then fill in each webhook's Sending and each folder's standing, four reads at a time. Making a webhook never waits on them.
- **A key's expiry is extended, never changed in place.** Extend… (`KeysModel.beginExtend`) is on a key that ends, offered only with `keys.manage`; without it the row says what MAPP isn't allowed to do, with Allow More…. The sheet offers the days later than the key ends now (7, 30, 90 and 365 from today) and Never, and sends only `expires_at` (a date, or `null`) with no `narrow_only`, which the server refuses a later expiry under (`keys-and-oauth/expiry-manage-lengthens`); the key's secret stays, so the sheet says nothing using it changes. Where MAPP is signed in with a key that expires (a test key; a signed-in app counts as having no expiry), the choices stop at that key's own end and Never is not offered (`keys-and-oauth/expiry-manage-ceiling`); MAPP reads that from `GET /keys/current` (`OwnerCalls.identity`), which a signed-in app's token answers with `403`. Until that is read nothing is offered, and the expiry row shows the failure with Try Again (`KeysModel.identityFailure`), since an end not known is not no limit. A refusal keeps the sheet and the choice, with the red ring on the pop-up and one line, and has the grants read again. A key that never ends has no Extend…. Making a key end sooner is not offered: Revoke ends it.
- **A sign-in that holds `webhooks.manage` and `keys.manage` sees every maker's webhooks.** The list is the server's (`events/webhook-owner-list`), grouped by maker (`WebhooksModel.groups`); a key's maker is told as the key, an expired one by reading the keys, and a maker the server has no name for as a revoked key or an app no longer connected. Which are MAPP's own is matched by identity with who MAPP is signed in as (`OwnIdentity`), never by name: the key's id for a key sign-in. A signed-in app has nothing to match, since a webhook's maker is its OAuth client ID, which neither the server nor the package tells an app about itself, so none of an app's makers is taken as MAPP's own: all stay read only and Delete…, and New Webhook… makes under an empty own group. If the identity can't be read the page shows the failure with Try Again, and when the permissions change what the list holds (Manage Keys lost or gained) the list is dropped and read again (`WebhooksModel.readAgainIfScopeChanged`). Only MAPP's own can be changed or sent again; another maker's page shows no Change, For, Sending, event switches or Redeliver, and Delete… asks first, naming the maker (`events/webhook-owner-delete`, `events/webhook-owner-no-change`). Without `keys.manage` the list is MAPP's own, with a row that says the others need Manage Keys and offers Allow More…. Turning Sending off asks first and names what it drops (the deliveries waiting). A change to the address, the events or the type is sent alone, with no version: the server changes each in place, and a webhook found gone is told as gone. A change to the events is built on the webhook read again just before it is sent, so an event another app turned on or off since the page was read is kept. That narrows the window and does not close it: with no version to send, a change made between the read and the send can still be replaced (withmarfa/marfa#3408 asks for one). Redeliver is shown on every delivery and enabled only on a failed one of a webhook that is on (`events/redeliver-inactive`); a refusal from the server, such as a delivery older than the audit retention, is shown as a line under the table.
- **A folder is read, not changed, here.** The package's client holds only the folder status call; reading and changing a folder's settings and files, and listing its paths, are the working copy's, which keeps no `system.*` rows and which MAPP does not use for folders. The list comes from the server's overview (at most 30 folders, by title; where it cut the list, the page says "Showing 30 of N" and that `marfa folders inventory` lists the rest) and each folder's copies from its status report. The report holds counts and problem codes and no file names. Removals that wait are decided on the machine that holds the copy, so the page says where to look and offers no action.

- **Backups keep to what the server offers.** Where backups go is a folder on the machine the server runs on, typed as an absolute path in a sheet (MAPP cannot browse that machine), changed with `PATCH /config` after a recent sign-in, which the call shows in place; an object store the server was set up with is shown and never changed here, and the server allows only one of the two. A restore is `POST /backups/{instance}/{name}/restore`: it asks first and lists what a restore leaves out, needs a recent sign-in, and keeps the sheet open if that is cancelled. After it, the page says how many items were added and how many were already here, and names any secret to set again by the name Monitoring gives it ("The heartbeat address and the PostHog project token."); a setting MAPP has no name for is only counted ("2 other settings are set on the machine <Marfa> runs on."), never told by its key. A refused folder change stays in its sheet, and only the interval and Keep Backups In pop-ups leave a line on the page, cleared when the sheet opens or closes. A server value with no time of day shows no time. Where the sign-in may not read the server's backup detail, the destination says Couldn’t Check, and a status with no count is worded as the server reported it ("Backups Are Failing", "Backups Are Incomplete"). Back Up Now with nowhere to keep a backup sends nothing and says so.
- **An update is followed to its end.** Update starts `POST /update` (Check for Updates runs the server's `release-check` job, then reads again) and the page then reads the update every two seconds. The server ends itself to start the new release, so a read that fails meanwhile is Restarting, not a fault; after 90 reads that go unanswered MAPP says it stopped waiting, and offers Check Again rather than Update, since the server may still be updating; any read of the status clears that. One follower reads at a time and ends with the page. The server answers a second start with the update that runs, in the same 202, so a start is followed whichever it was. Check for Updates is off while Check Automatically is off (the server runs no `release-check` job then and answers 404), and the row's line says why. Without `instance.maintain` the Check for Updates and Update buttons are one Allow More…. An update the server put back, or could not finish, is told in Needs Attention in MAPP's words with Try Again and no second Update. Where the server cannot update itself the page shows the server's own step, which is an instruction to copy, with Copy Steps.
- **Housekeeping lists the jobs an owner knows**: Back Up, Empty Recently Deleted, Thin Old Versions, Remove Old Activity, Remove Unused Files, Copy Files to Storage, Read New Files and Check for Updates, with the server's intervals and no Run Now. Its other jobs tidy the server's inside and are not listed. Confirm Date… reads health again and asks with the date the server's clock reads then, always with its year. `POST /clock/confirm` takes no date: the server trusts its clock as it reads at that moment, and answers it as `confirmed_at`; where that is not the day shown, the page says so under Needs Attention.

- **A type is changed as the server holds it.** `PUT /types/{id}` replaces the whole definition and has no version, so a change reads `GET /types` again, makes the one change (`TypeDefinitionEdit`, which the field edits use too) and sends the type back, with its guidance as it was: an app's sign-in is refused any change to guidance (`types/guidance-app-made`), and a replacement that left it out would remove it. Whether MAPP may write guidance is not decided, so the page shows it, with the guidance of the types above it, and sends none. The server's `400 invalid_schema` names a field in `details.errors`, which the page shows on the field it names with what was typed kept; a status word is made from what is typed (lowercase, an underscore for a space), and the server judges it. Lengths are counted in Unicode code points, as the server counts them. A type's provenance comes from `GET /types` (`provenance.origin`), since the catalogue holds none; a plugin's type is told apart before sending only by what the list says, and `common` stays reserved.
- **A new type is made under `user.`**: its identifier is its name in lowercase letters, digits and underscores, made unique among the listed types, and its base is the type it was made from. It declares no field of its own.
- **A status panel's Edit Statuses…** closes the panel and opens the item's type in Settings > Types.

## Left out

- Name and picture, which MAPP does not ask to change, and Add Passkey's list refresh after the browser returns.
- Overview: Update beside the release (a ready release links to Updates).
- Types: the fields, rules and Delete Type of an owner's type, which need a page for each field, and a field's menu's Edit the type in Settings, are not built yet. Guidance is not written (see above). A type's Show Items button.
- Sources: the Who May Write rule (`enforcement.source_allowlist`) and a source's own page.
- File Storage: Show… for the files nothing uses (a list of them has no use without their names) and the object store's secrets.
- History: the webhook deliveries are kept as long as activity (`audit_retention_days`), so they have no row of their own.
- Recently Deleted: the colored type mark on each row.
- Apps' Tidying settings and the Private Addresses switch, which need server or settings-model work.
- Webhooks: a webhook's signing secret can't be changed: the server changes it only by making a new webhook.
- Connectors: Add a Connector… (installing is the Plugins page's work and linking a machine is its own page), the mapping per kind, a connector's runs, the plugin it came from, the old board's Source, Key, Edits Put Back and Inbound Addresses rows (RSS's board S76 is an older design, so RSS is the same page as every connector), taking a connector off its machine (marfa-swift#545) and a multi-line secret.
- Folders: renaming, the tree of what a folder holds, the ignore and include patterns, the removal and addition limits, Read Every File Every, Stop Syncing and a button for removals that wait. Each needs the server's folder doors (`GET /folders`, `PATCH /folders/{id}` and `POST /folders/{id}/revoke`) or the paths of the `in-folder` edges, none of which the package's client offers. Read Every File Every is the copy's own setting, never the server's.
- Backups: Export Everything and Restore an Archive (files MAPP reads and writes itself, which On This Mac's export covers for the owner's own items), adopting another instance's backup folder, and choosing an object store.
- Keys: making a key end sooner, and the Needs Attention row on the list for a key that ends soon, which has no rule yet for how soon. The Overview shows the server's own concern for it.
- Updates: a confirmation before Update, which the board does not draw.
- Housekeeping: Run Now, and the jobs that only tidy the server's inside.
- Activity's total count and a "Who" or "What" that names the item, which the audit log does not give.
- Limits the board does not draw: the file inflation and memory caps, the inbound byte caps and the held and kept delivery counts, and the retention periods, which belong to the pages that own them.
- Telemetry's per-signal addresses and headers, its sample rate, service name and resource attributes.
