# The Marfa's half of Settings

Status: Account, Apps, Keys, Addresses, Webhooks, Folders, Activity, Monitoring, Limits and Start-Up are built, beside Overview and Recently Deleted. Folders only reads.

Where it lives: `MarfaSettingsPage`, `MarfaSettingsHost`, `OwnerCalls`, `ClientOwnerCalls`, `AccountModel`, `AppsModel`, `KeysModel`, `AddressesModel`, `WebhooksModel`, `FoldersModel`, `OwnerDrafts`, `OwnerPermissions`, `AccountPage`, `AppsPage`, `KeysPage`, `AddressesPage`, `WebhooksPage`, `FoldersPage`, `InstanceCalls`, `ClientInstanceCalls`, `StoredSettings`, `ActivityModel`, `ActivityPage`, `MonitoringModel`, `MonitoringPage`, `LimitsModel`, `LimitsPage` and `StartUpPage` under `MAPP/Settings/Marfa/`.

The Marfa's pages show and change what the server holds, as the owner. They stand alone: they reach only the parts and the host protocol ([Agreed designs](agreed-designs.md#settings), `MAPP/Settings/Marfa/AGENTS.md`). Every call needs the server and is never queued. A page opens only when the sign-in holds its permission; the server's answer wins over what MAPP thinks it holds, so a call refused with `403 forbidden` names the permission the server says is missing, and the grants are read again.

## What each page does

| Page | Permission to open | What it holds |
| --- | --- | --- |
| Account | none | The owner's username and email as the server holds them (read only), Change Password…, the passkeys (Rename, Remove, Add a Passkey…, which opens the server's own page) and the browsers signed in (Sign Out). |
| Apps | `grants.manage` | The connected apps. An app's page holds its access by type, which can only be narrowed, one row for its owner permissions (the same part as a key's), the keys it made and Disconnect. |
| Keys | `keys.manage` | The owner's keys and the keys apps made. A key's page holds its expiry (it can only be made to end sooner), its tier, its source (set once, shown with a lock), its access by type (narrowing only), one row for its owner permissions and Revoke. New Key… needs `keys.mint`. |
| Addresses | `config.manage` | The sign-in address, the other addresses and the websites allowed to call the server. |
| Webhooks | `webhooks.manage` | The webhooks this sign-in made. A webhook's page holds its address, what it is for (a type or every type), Sending, the events it sends (All Events and one each), its deliveries with Redeliver on every row, and Delete. New Webhook… is a sheet. |
| Folders | none: a folder is read as an item, under the access MAPP holds to every type | The synced folders the server lists, each with the copies that keep it (named by the sign-in that reports them), how each stands and what needs attention. |
| Activity | `audit.read` | The audit log as a table that is a page of its own, newest first, a page at a time, with a filter by kind (Access, Items, Settings, Housekeeping) and a search. |
| Monitoring | `config.manage` | The heartbeat, the error reports and the telemetry the server sends: a switch each, and the addresses and tokens they use, shown only as Set or Not Set. |
| Limits | `config.manage` | The limits the server lets the owner change, each a number with its unit inside: request sizes, rate limits, file reading, connector deliveries, live-update viewers and fetching files. |
| Start-Up | `instance.read` | What the server started with, read only: each setting's name, what it does and whether it is set, never its value. |

## Rules

- **`sign_ins.manage` is asked for from Account, never at sign-in.** The first time the owner chooses Change Password, or Allow More… beside the sign-ins or on Connection, MAPP asks for it. Cancelled, or approved without it, nothing opens and the page says so.
- **A password is never kept.** It lives in the sheet's fields until the call ends, is never logged, and is cleared on success, on Cancel and when the sheet closes. A wrong current password keeps both fields with the red ring and one line.
- **Narrowing asks first, and only narrows.** An app's access is sent with the access it was read as; a change made elsewhere is told as a conflict, the page reads again and nothing is changed. A key's access is sent with `narrow_only`, and narrowing a key or removing one of its permissions names the change and says it can't be undone. Narrowing a grant that holds only a write to Read Only sends a read in its place, never nothing. Disconnecting an app deletes its webhooks and leaves the keys it made working (`keys-and-oauth/grant-revoke-keeps-keys`, `events/webhook-grant-revoked`). Signing a browser out asks first, naming the browser.
- **Only a stale grant is "changed somewhere else".** A `409` that the server words itself (the sign-in address refusals, a new key's source held by another key) shows the server's words, the source's on the Source field.
- **A key is shown once.** The sheet that follows New Key holds the plaintext; closing it drops it. Copy marks the clipboard concealed and clears it after a minute if nothing else was copied.
- **An address is checked before it is written.** The server's `POST /config/address-check` says what adding, removing or moving would do, and an answer holds only for the address typed when it was asked: typing again drops it until the new address is checked. Moving the sign-in address shows the consequences in the sheet and writes exactly what was checked; the server asks for a recent sign-in, which the package shows in place. Every write names the instance that was read.
- **A draft is handed back when Settings closes or the app quits.** The address typed in Addresses and New Key's name and source go through `Notices.notKept`, as This Marfa's draft does (`OwnerDrafts`). A password is never kept, and a key's secret is never handed over: if the window closes while a new key is shown, MAPP says the key was made and its secret can't be shown again, so it can be revoked on the Keys page if it wasn't copied.
- **Owner permissions are counted, never all or nothing.** A key's page and an app's page each show one row (`OwnerPermissionsRow`), Look After This Marfa, with "None" or "3 of 14". With some held it opens a page of its own (pushed, Back returns) with one switch each; a switch can only be turned off, and turning it off asks first. New Key shows the same row with Choose…, which turns the sheet to a page of switches and back.
- **A sheet is shown by the window.** A page hands its sheet to `SettingsSheetPresenter` (`settingsSheet(presenting:)`), which draws it in the middle of the whole window, not under the toolbar; what it shows is read from the page's model. A sheet grows with what it holds up to the window's height, then its content scrolls between its title and its buttons. A field's placeholder says something its label does not (the address field's "https://"), never the label again.

- **Stored settings are written after a fresh read.** Monitoring and Limits send a change only once a read of `GET /config/settings` finds each setting it changes as the page showed it, and name the instance that was read; a setting changed elsewhere, or another Marfa answering at the address, is told in one line, the page shows what is there now and nothing is written over it. A write the server answers as a conflict is told the same way.
- **A limit is checked before it is sent.** Each limit has the contract's range, in what the server holds; sizes are shown in megabytes (1 MB is 1,048,576 bytes) with thousands separated. A value out of range, or not a number, stays in its field with the red ring and one line, and nothing is sent. A field emptied removes the stored value, so the server's default applies. A value is sent when the field is left or Return is pressed.
- **A secret is only Set or Not Set.** The server never returns one. It is changed by typing it again, in a sheet with a secure field that is never handed over and is dropped when the sheet closes; Remove clears it. The PostHog host and the project token are set together, as the server requires, and removed together. Turning the heartbeat or the error reports on is refused in one line while nothing receives them, before anything is sent.
- **The audit log is paged by cursor.** The server gives no count and no way back, so the page says which entries it shows ("1 to 20") and keeps where each page began for Newer. An action is put into MAPP's words; one the contract does not name is put into words from its own name.
- **No server wording shown as it is.** A server's refusal is shown only where it holds no setting name, code or route; otherwise one plain line says nothing was changed.
- **A webhook's signing secret is shown once.** The sheet that follows New Webhook holds it, and closing the sheet drops it. Copy marks the clipboard concealed and clears it after a minute if nothing else was copied (`OwnerClipboard`, which a key's secret uses too). If the window closes while it shows, MAPP says which webhook was made and that its secret can't be shown again, so the webhook can be deleted and made again. The page reads back only the last four characters.
- **A page shows its list before the rest is read.** Webhooks and Folders show the list as soon as it is read, then fill in each webhook's Sending and each folder's standing, four reads at a time. Making a webhook never waits on them.
- **A webhook sees only its maker's.** A key or an app reads only the webhooks it made, so the list is MAPP's own, grouped by maker (`WebhooksModel.groups`) so a group per app can join when the server lists them all. Turning Sending off asks first and names what it drops (the deliveries waiting). A change to the address, the events or the type is sent alone, with no version: the server changes each in place, and a webhook found gone is told as gone. A change to the events is built on the webhook read again just before it is sent, so an event another app turned on or off since the page was read is kept. That narrows the window and does not close it: with no version to send, a change made between the read and the send can still be replaced (withmarfa/marfa#3408 asks for one). Redeliver is shown on every delivery and enabled only on a failed one of a webhook that is on (`events/redeliver-inactive`); a refusal from the server, such as a delivery older than the audit retention, is shown as a line under the table.
- **A folder is read, not changed, here.** The package's client holds only the folder status call; reading and changing a folder's settings and files, and listing its paths, are the working copy's, which keeps no `system.*` rows and which MAPP does not use for folders. The list comes from the server's overview (at most 30 folders, by title; where it cut the list, the page says "Showing 30 of N" and that `marfa folders inventory` lists the rest) and each folder's copies from its status report. The report holds counts and problem codes and no file names. Removals that wait are decided on the machine that holds the copy, so the page says where to look and offers no action.

## Left out

- Name and picture, which MAPP does not ask to change, and Add Passkey's list refresh after the browser returns.
- Extending a key, which waits on a server release.
- Apps' Tidying settings, the Private Addresses switch and Raycast's own settings item, which need server or settings-model work.
- Webhooks of every app and key, grouped by maker, and ending any of them: they wait on a server release. A webhook's signing secret can't be changed: the server changes it only by making a new webhook.
- Folders: renaming, the tree of what a folder holds, the ignore and include patterns, the removal and addition limits, Read Every File Every, Stop Syncing and a button for removals that wait. Each needs the server's folder doors (`GET /folders`, `PATCH /folders/{id}` and `POST /folders/{id}/revoke`) or the paths of the `in-folder` edges, none of which the package's client offers. Read Every File Every is the copy's own setting, never the server's.
- Activity's total count and a "Who" or "What" that names the item, which the audit log does not give.
- Limits the board does not draw: the file inflation and memory caps, the inbound byte caps and the held and kept delivery counts, and the retention periods, which belong to the pages that own them.
- Telemetry's per-signal addresses and headers, its sample rate, service name and resource attributes.
