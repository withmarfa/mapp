# Model

The data model, free of SwiftUI: the `ItemLibrary` protocol, `MarfaLibrary` over a Marfa server's working copy, and `Libraries`, which holds the host and the library the windows read. Views reach a library only through `ItemLibrary`: what a view needs to know about an item comes from the protocol, such as `hiddenPropertyKeys(of:)` (the keys an item's page already shows elsewhere, so Properties leaves them out) and `Item.source` (what made the item; nil where the library does not know). Before changing `Marfa/`, also read `MAPP/Model/Marfa/AGENTS.md`.

## Items and types

- MAPP names no item type of its own. What it shows of a type, its label, fields, parent and recommended values, comes from the server's catalogue (`Catalogue`). Code never tests for a type by its identifier, with one exception: `TypeSymbol` gives Marfa's built-in types (`core.note`, `core.task` and the like) their symbols, and any other type takes its nearest built-in ancestor's.
- Folders are facts on items, never places: MAPP syncs no folders and has no Folders section, Move To or New Folder.

## Writes the library cannot always make

- Deleting for good (`purge`) needs the server, so `ItemLibrary.canPurge` is true only while it can be reached, and the views dim the command until then. Every other write goes to the copy's queue and can always be made.

## The sidebar

- The sidebar starts with Inbox, Recents and Favorites under no heading, then a Browse section (Items, Sources, Collections), then Types (`SidebarPlan.top`, `.browse`, `.library`). Items includes files. Favorites remains visible when empty unless hidden in the sidebar layout. Recents lists the `ItemLibrary.recentLimit` items edited last, so its row has no count. Sources and Collections open indexes without disclosure toggles. Types has an Edit control, shown only while the pointer is over the heading, which opens a popover using the existing per-library visibility settings, with Show All. `SidebarLayout.collapsed` remembers folded type rows. A row is a label and a symbol, never a sentence.
- The foot row (`SidebarFoot`) holds the instance's name, a status dot (`SidebarStatusDot`: orange connecting, red offline or unusable, none when reachable) and buttons for the browser Console (a profile icon), Settings and Recently Deleted, sitting in the list's bottom safe area so the system shows a material only while rows pass beneath; the name opens Settings at Library. Search has no sidebar button (⌘K, ⇧⌘P). New sits in the sidebar's toolbar row. Recently Deleted uses the ordinary item layouts and the library's restore and purge operations. Sources lists source identifiers observed on active readable items, not a complete registry of connected sources. There is no Views section yet: listing the instance's saved views needs `system.view` in the copy's slice (`MarfaSync.slice`) and the engine to keep those rows out of the item lists; until then, do not show a placeholder or add a local saved-view store.
- A collection is any item other items are filed under (`child-of`), whatever its type, so no type is special (`ItemLibrary.collectionTree`). The collection index shows two levels, by title. A collection's place lists what is below it, not itself. A list names an item's collection as the ancestor just below the top of its chain (`ItemLibrary.collection(of:)`).
- `ItemLibrary.itemTypeCounts` lists the catalogue's types that directly hold active items, file types aside. A type counts only its own items, never its subtypes, and its place lists exactly those, so the count is the list's length (`MarfaItemIndex.activeByType`; only Files takes subtypes). Labels come from the catalogue, symbols from `TypeSymbol`.
- Types nest by their identifiers below the vendor segment (`TypeNode.tree`): `aic.ticket.task` under Ticket, `aic.agent.session` under a group named Agent. A group of one gives way to its row; a nested row drops the words it repeats ("Session"). Siblings go by their branch's items, then label. A group, or a type with no items of its own, only folds open. Flat lists, such as the command palette and the toolbar's New menu (`ItemLibrary.creatableTypes`), tell two types with one label apart by their parent's, "Task (Ticket)" (`Catalogue.displayLabels`). A type whose last item goes has no row, and a collection no longer active has no place, so `Browser.placeRemoved` moves a window on either to All Items.
- `SidebarLayouts` keeps what the person hid, collapsed or moved, one `SidebarLayout` for each server (`Libraries.sidebarLayoutKey`). A place a layout does not mention, such as a new type, is shown after the placed ones. `SidebarPlan` is what the sidebar and Settings > Sidebar both read.

## Relationship names

- Both ends of a link are named by Marfa: `EdgeType.label` on the source end and `EdgeType.reverseLabel` on the target end (`EdgeTypeInfo.label(atTarget:)`). MAPP names no relationship and shows these as they come, never as localized keys or reworded. When the two are equal the relation is two-way (`EdgeTypeInfo.isTwoWay`), and an item's outgoing and incoming links form one list.

## The table

- The table view (`ItemTableLayout`) is worked out from the items a place shows, never stored: a column for each field their types declare, not the title or the text, leading with status, priority and assignee, then where each item is filed (the parent link, headed with Marfa's name for its child end, then Collection), then the rest, and Edited. A field few items fill, and the quiet ones (notes, url, place, precision), start hidden. A mixed table's column holds one type's field, so a cell offers its own type's values.
- A status sorts, groups and colors by its tone (`StatusTone`), so every type's word for it reads alike; the page header's ring follows the same tone (`PageHeader.Mark`). A place with statuses starts grouped by status with finished work folded, and ordered by priority, highest first. Empty cells sort last either way.
- What the person chooses (grouping, sort, filters, folded groups) is the window's, for each place (`Browser.tableOptions`); which columns show, in what order and width, is kept for each place in the defaults.

## Changing libraries and quitting

- `Libraries` owns the `MarfaHost` and the library the windows read: the host's `MarfaLibrary` while its copy is open. Its `mode` says what a window shows instead otherwise: with no server set (`unconfigured`), a page that asks the person to connect to their Marfa and opens Settings > Library; while a copy opens (`opening`), a wait; and when a set server's copy is not open (`failed`: a refused key, a copy that cannot be opened), a page that says so and points to Settings. There is no other library to fall back to.
- Before the host changes which library the windows read, and before the app quits, `Libraries.flushEditors` has every open page hand over its last edit (`EditorController.flushAll`), and the library keeps its writes on this Mac in the copy's queue (`ItemSource.queueSubmitted`). It never waits on the server, so quitting offline is not held up. Every window's unsaved titles are saved first, and a title still refused cancels the quit or the library change and names the item (see `MAPP/Editor/AGENTS.md`). Quitting waits a few seconds at most; a flush that fails or runs out of time cancels the quit, and the person is told why (a page given up on, a refused title, or a library still saving).
- A main window's `Browser` sits above the library, in `RootView`. A change of library resets the window (`Browser.adopt`: selection, place, search, new items being followed, and the window's undo), since they name items the other library may not hold.
- New makes the item at once (`Browser.startNewItem`, the one path for the toolbar menu, ⌘N and the palette) through `ItemLibrary.createItem`, like any create, and opens it in the page with the title focused. It opens when its library says it holds it, not when the create is sent (`finishNewItem`); the library may take a moment, and a second New waits meanwhile. A create the library refuses is given up and the library tells the person. `Browser.newItems` follows each item New made until the person leaves it. When the page lets go of it (another item is selected, the window closes, or the app quits or changes library), `leaveNewItem` moves it to Recently Deleted if it still holds nothing the person put there (`NewItem.isUntouched`). An item counts as touched once the library has made any write to it after the create, or another item points at it (`ItemLibrary.wasTouched`: `MarfaLibrary` records the item each write names in `submit`, since its copy shows a title, a tag or a link only when the source reports it, and reads the connections held by other items). Whatever else changed the item shows in the copy, which is compared with the baseline taken when the library first showed it: the title it was made with, a blank body, and no tags, properties, connections or parent beyond it. A window closed by its button decides with `closing: true` like a quit, so an empty item goes at once. It is never purged. A create still queued cannot be withdrawn, since the working copy only withdraws blocked or refused writes, so an empty item is deleted after its create, and offline both writes wait in the queue.

## Telling the person

- Everything the app tells the person in an alert goes through `Notices`, which the host makes and gives to every library it opens (`ItemLibrary.notices`): something a library could not do (`tell`), a change it could not keep (`notKept`), and an address that sends the key unencrypted. Each waits in order until one window in front shows it and the person answers, so a notice from a library the windows have left is still told, and a later one never replaces it. `Notices.show(in:copying:)` decides which window shows it, one at a time, released when that window answers or closes; the person's answer names the notice by its `id`. Changes not kept gather into one notice until it is shown, and its text goes to the clipboard the first time it is shown (`View.notices`) and is never written again; a change not kept after that waits in a notice of its own, so nothing on the clipboard is written over before the person answers. A quit waits for a change not kept that no window has shown, as when no window is open, and tells it in an alert of its own (`Notices.tellBeforeQuitting`). Add no other route.

## Code Review Rules

- **Named type.** Flag code that tests for an item type by its identifier, or gives one a label, field or behavior of its own, outside `TypeSymbol`'s built-in symbols.
- **Folder as a place.** Flag a change that brings back a folder as a sidebar place, a move between folders, or a folder MAPP keeps or syncs itself.
- **Fallback library.** Flag a change that shows anything but the connect, waiting or failure page while no server's copy is open.
- **Unflushed switch.** Flag a change of library or a quit that does not first flush the open pages (`Libraries.flushEditors`), or that goes ahead when the flush fails. A window close waits for its editor's flush the same way (`EditorCloseDelegate`).
