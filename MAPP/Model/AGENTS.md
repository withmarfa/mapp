# Model

The data model, free of SwiftUI: the `ItemLibrary` protocol, `MarfaLibrary` over a Marfa server's working copy, and `Libraries`, which holds the host and the library the windows read. Before changing `Marfa/`, also read `MAPP/Model/Marfa/AGENTS.md`. Read a type's doc comment before changing it.

## Items and types

- MAPP names no item type of its own ([docs/marfa-and-mapp.md](../../docs/marfa-and-mapp.md)). A type's label, fields, parent, status words, groups and icon come from the server's catalogue (`Catalogue`). Code never tests a type by its identifier, except: a child of `core.task` carries `due_at` and `priority` (`Catalogue.isTask`), `PageHeaderKind` walks up the parents for an item page's header, and `ListRowStyle.fromFields` does the same for a list row's starting style (`core.highlight`; a file type by `Catalogue.isFileType`, a person by `PageHeaderKind`). A row's other fields (a task's `completed_at`, `recurrence`, `assignees`; a highlight's `color`) are named in `MarfaMapping`, never in a row's code. A task's priority takes its color by rank (`OptionTone.tone(of:in:isPriority:)`), never by the option's word. A collection is a type that plays the `container` role (`Catalogue.isCollection`), never a type's name.
- A field is a status only when it is of the `status` kind, and a list of entries only when it is an `array` of `object` with `items_fields` (`Field.Kind.list`), whatever it is called. Name no field in code. `ListEntries` is the only place that changes a list; every edit returns the whole list with the other entries as they were. The person's work on a list lives in `ListEditing`, not the rows.
- Folders are facts on items, never places: MAPP syncs no folders and has no Folders section, Move To or New Folder.
- What the item page shows of a type (`PagePlacements`), the sidebar layout (`SidebarLayouts`), column widths and a saved view's Mac settings (`ViewLayouts`) are MAPP's own settings on this Mac, never written to Marfa. [docs/settings-storage.md](../../docs/settings-storage.md) lists them. An unreadable stored sidebar layout, page placement or view setting is set aside under its own key (each store's `setAsideKey`), never removed.
- Which properties sit under an item page's title is decided once, in `PagePins` (pure, no SwiftUI), from `PagePlacements` and the header's `PageHeaderLead`; its doc comment says what a pin shows, leaves out or pushes out, and the page draws and decides nothing ([docs/item-page.md](../../docs/item-page.md)). A list pin carries every value in its help (`PropertyRow.help`); the property block and the right sidebar show every value. Customize Layout stores through `PagePlacements.apply` (`PageLayout`, pure) as the type's pins, what the page shows and `rowOrder`, and the sidebar half as `Choice.sidebar` (`SidebarSection`). Linked From's place is the one `linkedFrom` setting, which both halves read and write. Layout changes no item, so a read-only item can be laid out.
- Change Type is one queued edit (`ItemLibrary.changeType`, planned by `TypeChange.plan`), so it works offline. Nothing is left under a key the new type does not read, written twice, or dropped.

## Commands and writes

- Every item command takes the whole selection, files too, and writes each item through the queued, offline-safe edit it would use alone, in one undo step. An item a command can't change is counted in `BatchSkips` and told in one notice (`ItemLibrary.tellSkipped`).
- Moving several items to Recently Deleted asks first; one does not, since Undo puts it back. Delete erases only items already in Recently Deleted, after their own dialog.
- Change Type, Undo, Redo and Restore wait for every open page to hand over its last edit and judge on the item as it then stands, so a change made elsewhere is refused or worked on, never overwritten.
- Deleting for good (`purge`), making, updating, renaming and deleting a view, choosing a type's icon, and changing This Marfa's settings need the server and are never queued. `ItemLibrary.reachesServer` is the one rule that offers them; the server's refusal is told. Saving a view's layout, columns or cards alone is the Mac's own and needs no server. Every other write goes to the copy's queue and can always be made.
- What a person typed into a sheet or panel (a new view's title, a rename, This Marfa's draft, quick add's draft) stays there until the library takes it. A window that closes or changes library hands it over through `Notices.notKept`, and so does a panel that ends in any way but the person's own Cancel; only Cancel drops it.
- Quick add (`QuickAdd`, `Browser.saveQuickAdd`) never writes an empty item, makes it in one create so a required field is never set after, and never drops text or files the chosen kind cannot keep: adding waits until the person removes them.
- Files from outside (a Finder drop, a drop on a collection, Import from iPhone) become items only through `Browser.importFiles`, and what leaves in a drag is an `ItemReference`: its identity inside the app, a file named after the item outside it. An import's files go to the library they were dropped on; only the window's own steps (selecting, revealing) stop. Quick Look is shown temporary copies (see `BrowserQuickLook`).

## Places, views and search

- `SidebarPlan` is what the sidebar and Settings > Sidebar both read; `SidebarPlace` is the one definition of a place's symbol, destination and count. A file attached to another item is cut from the places in one place, `MarfaItemIndex.standalone`, so lists and counts agree.
- A type counts only its own items, never its subtypes (`MarfaItemIndex.activeByType`), so a count is its list's length. Include Subtypes changes only what the list shows (`Browser.placeItems`).
- A window whose filters differ from its saved view's lists a preview (`ItemLibrary.previewItems(ofView:query:)`, `ViewDraft.previewQuery`): the copy's answer to the view's query with the conditions shown as chips taken out, which the chips then narrow locally. It reads the copy, works offline and writes nothing; a query the copy refuses lists the view's own list, said once.
- Saved views live on the server. A view write is based on the version the window read, so a change made elsewhere is refused, never overwritten. What a view cannot hold is left out and named first. The Edit View panel (`ViewPanel`, `Browser+ViewPanel`) holds nothing back: every change shows as it is made, and Done only closes it (a new view is made by Done, and Escape before Done makes nothing). `Browser.choicesChanged()` is the one funnel: it compares the window's choices with the last it observed, registers one undo step, and for a saved view writes Marfa's part (name, query, sort, group) at once through `library.changeView`, serialised per view and never queued. A refused or failed write keeps the window's choice and tells the person; an Undo after one writes nothing and never overwrites a change made elsewhere. The Mac's part (`ViewLayouts`, keyed by view ID) is stored as made, with its own undo step, and never written to Marfa. Only `Browser.forgetView`, reached from `Browser.deleteView`, forgets it: deleting a view removes both parts, but a view missing from a list proves nothing, since a failed read can publish an empty list. [docs/views-and-lists.md](../../docs/views-and-lists.md) says what each part holds.
- A view, a command or the palette asks the browser for a place's content (`Browser.tableContent(in:)`, `sections`, `paletteIndex`) and never builds an `ItemTableContent` or reads the library's items itself. A new `ItemLibrary` must bump `contentRevision` when its items or catalogue change, and `membershipRevision` when an item comes, goes or changes which places hold it.
- A column width is recorded only from a drag of the divider (`ColumnWidthTracker`), never from a layout measurement.
- MAPP shows the core's name and preview (`Item.name`, `Item.displayTitle`; `title` is only what it writes), labels (singular where one item's kind is picked, plural for counts), dates (`Marfa.ItemDate`), excerpts and `types`/`states` filters, and parses and filters none itself. Search runs in the working copy, never the server. A result list from a copy that is filling or behind (`isIncomplete`) never says nothing matches; an excerpt shows only while it still describes the item. Relevance never changes the stored sort.
- Relationship names are Marfa's (`EdgeType.label`, `reverseLabel`), never reworded.

## Remote pictures

- A picture at a web address is fetched only by `PictureFetcher`, only when `WebPictures.answer` allows it, and only for the editor's `pictures` message or a sealed page's `SealedPictures`. A saved file or the cache answers without a request; printing and export never ask the website.
- `PictureAddressPolicy` checks every address and redirect before a request: `https` only, no sign-in, and no private, local or reserved address by name or by any resolved answer. `PictureFetcher` offers no identity or password and tells a picture's kind by its bytes, never SVG.
- **Known limit: DNS rebinding.** `URLSession` resolves the name again when it connects, so a server that answers the check with a public address and the connection with a private one is not stopped. Do not claim more than this in the interface or the docs.
- A sealed web page (`SealedWebPage`) has no network, stored data or WebRTC, and reaches only its own pictures.
- `PageAnalyzer` loads a document into a sealed page of its own and never changes the page that is shown or the stored file. A failure or a timeout is a document with no article, and a cancelled analysis throws, so a late answer never reaches the next item. Every script that runs on a document reads it only through `SafeDOM` (see `PageAnalyzer`'s doc comment).

## Changing libraries and quitting

- `Libraries` owns the `MarfaHost` and the library the windows read. With no copy open, a window shows the connect, waiting or failure page (`Libraries.mode`) and no other library.
- Before the host changes library and before the app quits, `Libraries.flushEditors` ends the open value panel (`ValueEditPresenter.handOff`), has every open page hand over its last edit and every unsaved title saved; a flush that fails or runs out of time cancels the step and tells the person why. It never waits on the server, so quitting offline is not held up.
- A change of library resets each window (`Browser.adopt`): selections name items the other library may lack.

## Logs, reports and notices

- `MAPP/Model/Telemetry/` is the one place for logs and signposts (`Telemetry.logger(_:)`, `Telemetry.signposter(_:)`); never make a `Logger` of your own. `Cost` stays the one mechanism the `Measure` plan reads.
- **Never log a person's text, titles, property values or keys.** Log kinds, durations and counts, with `privacy: .public` for those alone. Name an item by a count, never its id or title. A message that may quote the person's text uses the default (private) privacy.
- **Reports to WithMarfa.** Everything the app sends leaves through `Telemetry+Reports.swift`, a closed list of calls over `Reporting`; no call site reports itself, and only `MAPP/Model/Telemetry/` imports `MarfaTelemetry`. A report carries only fixed words, numbers and flags: never a person's text, an item's id or title, the server's address, a path, or an error's message. `Reporting.Gate` keeps tests, previews and the isolated host from reporting.
- Every alert to the person goes through `Notices` (`tell`, `notKept`); add no other route. A change not kept goes to the clipboard the first time it is shown and is never written over before the person answers.

## Code Review Rules

- **Named type.** Flag code that tests for an item type by its identifier, or gives one a label, field or behavior of its own, outside `PageHeaderKind`'s header choice, `Catalogue.isTask` and `ListRowStyle.fromFields`.
- **Library type leaks.** Flag a view, command or editor change that names `MarfaLibrary` outside a preview, offers Delete Immediately without checking `reachesServer`, or names an SF Symbol for a type. A type's icon comes from the catalogue (`Catalogue.icon(for:)`) and is drawn by `TypeGlyph`, which keeps a table by icon id.
- **Folder as a place.** Flag a change that brings back a folder as a sidebar place, a move between folders, or a folder MAPP keeps or syncs itself.
- **Fallback library.** Flag anything but the connect, waiting or failure page while no server's copy is open.
- **Unflushed switch.** Flag a change of library or a quit that does not first flush the open pages (`Libraries.flushEditors`), or that goes ahead when the flush fails. A window close waits for its editor's flush the same way (`EditorCloseDelegate`).
- **Picture fetched another way.** Flag a web picture fetched other than by `PictureFetcher` after `WebPictures.answer`, an address `PictureAddressPolicy` did not check at each redirect, or a claim that DNS rebinding is closed.
- **Person's text logged or reported.** Flag a log, signpost or report that carries a person's text, a title, an item's id, a key or an error's message as public.
