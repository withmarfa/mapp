# Editor host

The Swift side of the note editor: the web view, the controller that drives the page, the bridge's messages, the `mapp-embed:` scheme, and printing. The page's own source is in `editor/`; read `editor/AGENTS.md` before changing the bridge.

## Web view

- Use AppKit's `WKWebView` in an `NSViewRepresentable`, not SwiftUI's `WebView` and `WebPage`. An editor needs what they do not offer: printing, filtering WebKit's context menu rather than replacing it, routing Undo to the page's own history, dropped files, and focus. Revisit only when Apple makes editing, printing, and the scroll edge public in them.
- `WebViewChrome.swift` sets two WebKit settings that are not public API, as Apple's own `WebView` does: a clear background (`drawsBackground`) and the soft edge under the toolbar (`usesAutomaticContentInsetBackgroundFill`). Each is set only while WebKit responds to its selector, and the page must still work without it: it then keeps its own background and stops below the toolbar. Add another private WebKit setting only on the same terms: Apple's own `WebView` uses it, it is guarded the same way, and the page works without it.
- The navigation delegate allows only the page itself and `mapp-embed:` requests. Keep every other navigation cancelled.
- The page keeps ⌘[ and ⌘] while it has the keyboard (`EditorController.isFocused`): it outdents and indents a list item and moves between table cells with them. The View menu's Back and Forward (`AppCommands`) give those keys up then and keep them for the list, the sidebar and the gallery.
- A window makes its editor once: the view keeps an `EditorSlot` in `@State` and reads the editor from it in `body`. SwiftUI makes a view's value again each time its parent updates and keeps only the state it stored first, so an editor made in a view's initializer builds a web view and loads the page in a process of its own, only to be thrown away.

## Embedded files

- `ItemLibrary.embeddedFile(_:in:)` in `EmbeddedFiles.swift` is the one place an embed becomes a file. Callers use `openEmbeddedFile(_:in:)`, which resolves through it and opens the result with `OpenFile`: the `mapp-embed:` scheme, the page's images for printing, Open and Show in Finder, and gallery thumbnails. Do not resolve an embed path anywhere else.
- It reads the path or name as Marfa's core does (`EmbedPaths`): relative to the note, `/` from the folder's root, a bare name nearest the note first, without regard to case. Keep it matching the core.
- It serves only a regular file inside the notes folder, reached without a symbolic link or a name starting with a dot.
- `OpenFile` opens the file with `O_NOFOLLOW_ANY` and keeps it only if the descriptor's own path (`F_GETPATH`) is inside the folder. Everything the page is told or served comes from that descriptor, so a folder changed after the check cannot put another file behind it. Never reopen by path after the check.
- The scheme handler streams the file in pieces and answers byte ranges, which WebKit's media playback needs.
- `EmbeddedFiles.opens` decides what Open may hand to another app. It never hands over a file that might run (a program, a script, a web page, a link file, anything marked executable, or a kind it cannot tell); such a file is shown in the Finder instead.

## Saving

- Each load of a note gets a generation, and each edit reports the generation and the version of the text it was typed on (`EditorController`). Never save an edit without its version, and never let an edit from an earlier generation save into the note now on the page.
- A failed capture of the page's last edit cancels quitting, closing the window, or changing libraries, and the person is told. The editor stays open so the text can be recovered.
- Images go into a note through `library.attach(_:to:)`, and the page inserts the returned link with `insertImages`. The editor then saves it like typing.

## Header

- The header is drawn in the page (see `editor/AGENTS.md`). `MAPP/Views/ItemPageHeader.swift` carries out its events: it saves the title through `setItemProperty` on Return or when the title loses focus. Title typing is undone by WebKit's own steps. A refused status or a refused Remove Parent sets a flag on the item's draft (`DetailsPresentation`), which the header shows as its own message; nothing is dropped silently.
- A title is editable only where the library can set it (`ItemLibrary.canSetTitle(of:)`). A library without files cannot retitle an item titled by its first line.
- Each window's editor holds that window's title drafts (`EditorController.titleDrafts`, a `DetailsPresentation` keyed by item), so an unsaved or refused title survives switching notes. A refused title is kept until it is saved or discarded.
- `EditorController.flushAll` tries every unsaved title again before it captures the pages. Where a window or the library goes (quitting, changing library, closing a window through `EditorCloseDelegate`), a title still refused stops it as a failed capture does, and the window holding it comes forward and names the item. Deleting items or a folder calls `flushAll(leaving: false)`, which saves titles too but never waits on a refused one.
- When a window goes, it calls its editor's `windowWent()`, which drops the window's drafts and removes the editor from `EditorController.open`, so neither takes part in later flushes while SwiftUI still holds the editor for a moment. Closures the editor keeps (header events, observation tracking) and the Format menu's focused editor hold it weakly. A strong capture keeps a closed window's editor, web view, and drafts alive, and `flushAll` would still visit them.
- A pin's menu opens under the pin's frame, which the page sends in its own coordinates. `EditorController` converts it to container coordinates, allowing for the covered top and the scroll offset.

## Linking to notes

- A link names a note by a spelling the library resolves to that note alone, from the note it is written in (`ItemLibrary.bodyLink(to:in:)`). In a Marfa library that is the title, unless another note goes by it, the title is shaped like an identity, or the note being written in already links that name to another note (`Item.establishedLinks`, read from the package's own `links(in:)` result, since Marfa keeps the first target of a spelling within a note); then the item's identity names it, with the title as the label (`[[identity|Title]]`). In a notes folder, links are read afresh, so nothing is established: the spelling is the title, else the path, else the identity the file declares, whichever the connection index resolves to that note alone (`NoteConnectionIndex.resolution(of:)`). Where none does, there is no link and the person is told. A spelling a link cannot hold (`[`, `]`, `|`, `#`, `\`, a line break, edge whitespace) is not used (`NoteLinks.canSpell`), nor is a title shaped like an identity (`NoteLinks.canName`), because a link reads that as the item with the identity, not as a title. A file is not a note. A link typed in double brackets becomes a link and is saved as typed, so the page cannot check its spelling; the library resolves it when the note is saved.
- `NoteRequests` is the `notes` message handler. Suggestions come from `NoteLinks.Index`, which runs off the main actor on a copy of the items and keeps titles folded, so typing never waits on a large library. It offers only a title no other note goes by, that is not shaped like an identity, and that the note being typed in has not already bound to another note, since InkKit writes the name it is given and cannot say which note. Its scores follow `PaletteMatch` from its own cache; keep `PaletteMatch` as the palette needs it.
- Link to Note asks the person in `NoteLinkPicker`, a sheet of `NotePage` so every window that shows a note has it. The page's request waits on `EditorController.chooseNoteToLink`. The sheet hands back the note's identity, and `finishLinkRequest(choosing:)` reads the link from the library as the note is when it is chosen, so a rename or a new twin since the list was made is seen. Every other end answers the page with nothing, exactly once: Cancel or Escape (the sheet's `onDismiss`), a document replacing the one the command was typed in (`show`), leaving the note, the window going, and the page's process ending. A request made after the window went is answered with nothing.
- Following a link: a command-click on a rendered `[[link]]` reaches `EditorController.openNote(_:from:)`, which asks the library what that very link means (`ItemLibrary.resolveLink(_:in:)`, given its name, heading and alias) and never guesses by title. Only `resolved` opens a note, through `onOpenNote`, which the window carries out as choosing the note in the list does (`Browser.open(linked:in:order:)`: the window's place, search and undo are left alone unless the note is not in the list, which then shows All Items, and the keyboard stays with the page). Every other answer (missing, more than one note, not looked up yet, refused) opens nothing and beeps (`onUnopenableLink`); no note is made for a link. The heading is scrolled to once the note is on the page (`pendingHeading`), and only if the note has it. A click in a note the page has since left, or in a window that went, is ignored. A window of its own (`NoteWindow`) shows the linked note by handing over its item, as `MainView` does by selecting it; wire `onOpenNote` wherever an editor is made, and ask for the keyboard for the note it opens (`EditorController.focus`), as a main window does with `focusRequest`. A new item asks for its title (`focus(_:onTitle:)`, which calls the page's `focusTitle`), which the page gives once it shows that item. `EditorController.onLeave` also says whether the window or app is closing (`closing`), which is when a new item left empty is decided even though the page still shows it.
- Known limit: InkKit (the version in `editor/package.json`) hands `open` and `resolve` only a link's decoded target, fragment and label, not its source text or range. So `[[Plan]]` and `[[Plan|Plan]]` look the same to the page, and a link whose text Marfa splits differently from InkKit (a backslash before `|` or `#` in the name) is never matched to its binding. Both stay a link the app does not open until InkKit offers the authored text (for example a `raw` field on `WikiLinkReference`).
- A notes folder reads a link by its name alone, through its connection index (title, path or declared identity, ignoring case); two notes going by one name are ambiguous. A Marfa library reads the very link, by its name, heading and alias, from what the copy bound that spelling to (`Item.boundLinks`, the package's own `links(in:)` result; `NoteLink(reading:)` takes the backslash escapes out of Marfa's text as InkKit does, and keeps the spaces inside the brackets, since Marfa tells `[[Plan | a]]` from `[[Plan|a]]`): two links to one name can name two notes, and a renamed note stays the target of the link bound to it. An identity names the item that holds it whatever else is titled. A link the copy has not bound, as one just typed, is `pending`, never guessed from the titles the library holds, since the server may hold another note with that title; it opens once the copy binds it, and the page shows it as an ordinary link, not a missing one.
- The page draws a link whose name no note answers to (`resolve` answered `missing` only) differently. The `resolve` request is answered at once from the library, and `EditorController.watchLinks` tells the page when the library's notes change, once they pause. Never rewrite a note to mark a link.

## Printing and PDF export

- `PrintDocumentRenderer` renders InkKit's frozen portable HTML in a separate WebKit view, with images supplied through the checked file path above and readable descriptions for other files.
- PDF export renders the complete document, stops at 200 pages or 64 MB, and writes the destination atomically only after rendering succeeds, so a failed export leaves an existing file unchanged.

## Code Review Rules

- **Embed escapes the folder.** Flag any path that reads, serves, or opens an embedded file without `openEmbeddedFile(_:in:)`, follows a symbolic link, or reopens by path. Safe path: use the descriptor `OpenFile` returns.
- **Runnable file opened.** Flag any route that hands a file to another app without `EmbeddedFiles.opens`.
- **Editor made for every view value.** Flag an `EditorController`, a web view, or another costly object made in a view's initializer or given to `State(initialValue:)`. Safe path: `EditorSlot`, or make it in `.task` as Apple's `State` documentation shows.
- **Unguarded private API.** Flag a private WebKit setting set without a `responds(to:)` check, or a new one that Apple's own `WebView` does not use.
- **Link request left open.** Flag a path that ends Link to Note without answering the page once, or that writes a link without `bodyLink(to:)`.
- **Edit saved to the wrong place.** Flag a save without the version it was typed on, or one that can land in another note after the page changed notes.
