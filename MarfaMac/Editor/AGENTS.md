# Editor host

The Swift side of the item editor: the web view, the controller that drives the page, the bridge's messages, the `marfa-embed:` scheme, and printing. The page's own source is in `editor/`; read `editor/AGENTS.md` before changing the bridge. The types named here carry the detail in their doc comments; read them before changing their behavior.

## Web view

- Use AppKit's `WKWebView` in an `NSViewRepresentable`, not SwiftUI's `WebView` and `WebPage`, which lack printing, menu filtering, Undo routing, dropped files and focus. Revisit only when Apple makes editing, printing, and the scroll edge public in them.
- A private WebKit setting is allowed only when Apple's own `WebView` uses it, it is set only while WebKit responds to its selector, and the page still works without it (`WebViewChrome.swift`).
- The system's scroll edge never reaches the page, and the window's toolbar draws no background, so the app draws its own band under the toolbar (`ToolbarBand`, `bandsToolbar()`, `bandsFoot`). Do not rely on the system's edge for any view in this window.
- The navigation delegate allows only the page itself and `marfa-embed:` requests. Keep every other navigation cancelled.
- A window makes its editor once, in an `EditorSlot` held in `@State`. An editor made in a view's initializer builds a web view and loads the page in a process of its own each time SwiftUI makes the view's value again.
- Inkkit owns selection painting. The bridge only reports whether the web view has the keyboard in the key window (`window.editor.setHostActive`) and never changes focus or history to recolor a selection.

## Saving

- Each load of an item gets a generation, and each edit reports the generation and the version of the text it was typed on (`EditorController`). Never save an edit without its version, and never let an edit from an earlier generation save into the item now on the page. The last few generations are kept; a `changed` for an older one, or one that does not decode but carries readable text (`EditorMessage.unreadableChange`), is handed back through `Notices.notKept` and logged by kind only, never dropped.
- The sidebar's Outline lists the headings the page reports (`EditorMessage.headings`, kept as `EditorController.outline` only for the load now on the page and the item it holds) and reveals one by ordinal under the generation that list came with. Nothing in the app parses an item's headings; before the page has reported for the item, the Outline has no rows.
- An item whose text the library cannot give (`body(of:)` is nil) is not opened: the page is emptied and made read-only under a generation no item owns (`clearPage`), so nothing typed there reaches any item.
- A failed capture of the page's last edit cancels quitting, closing the window, or changing libraries, and the person is told the recovery step, never the page's or WebKit's text (it goes to the log). A page that cannot hand over its edit within `EditorController.flushLimit` is given up on and the person is told. A page whose process ends, or whose own load fails, after it had been ready may have lost the person's last typing (`EditorController.pageWentDown`): they are told once. While it comes back, a quit, window close or library change fails (`flush(leaving:)`), as does one under way when it went down; choosing or leaving an item goes ahead and shows on the page once it is back. A page that ends again before it shows the item and within `settleTime` of being ready, or is not ready within `reloadLimit`, cannot come back and is not reloaded again; its notice names the item then on the page and replaces the first one unless a window has shown it (`Notices.withdraw`), and it holds leaving only until the person answers (`lossHoldsFlush`). A page still loading for the first time holds nothing typed. Flushes take turns; a close, quit or library change asked for during a hand-over waits for it (`EditorCloseDelegate`).
- Writing Tools run on the page (`writingToolsBehavior = .complete`). While `isWritingToolsActive`, an edit is held in `heldEdit` and not saved, so a half-finished rewrite never reaches the item; the finished text saves when the session ends (key-value observation of `WKWebView.isWritingToolsActive`). Anything that ends the held edit's generation (a flush, `show`, `clearPage`, the page's `ready`, its process ending or its own load failing) releases it first, so it is saved against the version it was made on and never replaced.
- Link in the Format menu asks for an address in a sheet (`WebLinkRequest`). The page reads what the person typed with Inkkit's `normalizeLinkAddress` (`window.editor.normalizeLinkAddress`), and the app sets the link only when it answers an address; an empty address is refused, and Remove Link takes the link off. On a link the sheet starts from the caret's `href`. The app keeps no address rule of its own. The page passes the app only an address Inkkit's `canOpenLink` allows, for `openLink`.
- Images go in through `library.attach(_:to:)`, and the page inserts the returned links, saved like typing. One image that fails never stops the others, and each one not placed in the text is named to the person. Files attached in quick add wait in `EditorController.pendingEmbeds` until the page shows that item, and any that cannot be written into the text are named (`notInText`); the item's text is untouched. Images dropped or pasted are placed again after the next paint when the page refuses them for folded text, and named (`reportUnplaced`) if they still cannot be placed. Text the person typed into folded text is dropped by Inkkit and cannot be handed over (`EditorMessage.hiddenText`), so they are told it was not added.

## Embedded files and pictures

- `ItemLibrary.openEmbeddedFile(_:in:waiting:)` in `EmbeddedFiles.swift` is the one place an embed becomes a file. Do not resolve an embed anywhere else, and run no link or embed rule of the app's own: the library matches the embed's exact text against what Marfa's core bound it to (`Item.boundEmbeds`).
- `OpenFile` opens the file with `O_NOFOLLOW_ANY` and keeps it only if the descriptor's own path is an ordinary file inside the expected directory, under no dot name. Everything the page is told or served comes from that descriptor. Never reopen by path after the check.
- A value the page asks to edit (`editValue`, with the row id and the value's rectangle) opens in `ValueEditPresenter` under that rectangle, anchored on the editor's container as `headerMenu` is. Swift decides which rows are editable (`PropertyRow.editable`, from `Item.isEditable` and `canEditTags`, so one place settles it); the status and parent pins and every other value open the same panel, a yes or no flips on the click, and an empty value is a row of kind `empty` that opens it. The write goes through the library as the inspector's does, and a refused write is told in the panel, never by a flag on the page. A field's name on the page sends `fieldMenu` (the row id, whether the menu holds Edit Value because the value follows a link, the name's rectangle and the viewport height); Swift builds the menu from `FieldMenu` and pops it up under the name in `EditorController.popUp`, and the page never decides what a field may do. A row dragged by its key (`moveRow`, carrying the order the page shows) goes through `PageLayout.listing` and `PagePlacements` as Customize Layout's does, so it sets the order for the type and changes no item.
- A file card's Quick Look (`quickLookEmbed`, `EditorController.quickLookEmbed`) resolves the embed through `openEmbeddedFile` as Open does, for the item on the page only, and shows the kept copy's checked URL in the one shared panel (`EditorController.quickLook`, `QuickLookRequest`, `.quickLookTaken`). It runs nothing, so `EmbeddedFiles.opens` does not apply. A reference it cannot resolve is told to the person; it never changes the item's text.
- `EmbeddedFiles.opens` decides what Open may hand to another app: never a file that might run, which is shown in the Finder instead. The kept copy of a file is read-only.
- A picture at a web address is asked through the `pictures` handler (`PictureRequests`), never `embeds`. `PictureRequests.reply` is the one place the page's question becomes `WebPictures.answer`, after a saved file from the same address (`ItemLibrary.openSavedPicture`). The scheme serves only a file the cache or the item holds, never a fetch. How a picture is fetched and kept is in `Model/AGENTS.md`.
- `EditorController.watchEmbeds` and `watchLinks` tell the page only which embeds, saved pictures or links may differ, so the page redraws those alone. `watchLinks` follows `namesRevision` (a title or a display name) and `membershipRevision` (an item coming or going, or a type's icon), not the library's items and not `contentRevision`, which a keystroke moves. Showing a picture or marking a link never rewrites the item. How links look (`LinkLook`) reaches the page with the rest of the page style (`applyStyle` calls `setLinkStyle`), so a change applies to open pages at once.

## Header

- The header is drawn in the page (see `editor/AGENTS.md`); `MarfaMac/Views/ItemPageHeader.swift` builds its data and carries out its events. The title saves through `setItemProperty`. A refused status, parent removal or title is shown and kept, never dropped.
- Customize Layout is the window's (`DetailsPresentation.isCustomizingLayout`), not the editor's: the header reads it, the page's control posts `toggleLayout`, and Escape from the page ends it (`EditorController.onEscape`). Linked From in the row above the title ends it and opens the sidebar.
- The editor builds the header again only when what it reads changes (`EditorController.showHeader`). Never read `contentRevision` or a whole list while building it, or an edit anywhere rebuilds the open page's header.
- A title is editable only where `ItemLibrary.canSetTitle(of:)` says so. Each window's unsaved and refused titles live in `EditorController.titleDrafts` until saved or discarded; `flushAll` tries them again, and a title still refused stops a quit, a library change or a window close and names the item.
- When a window goes, `windowWent()` removes its editor from `EditorController.open`. Closures the editor keeps, and the Format menu's focused editor, hold it weakly, or `flushAll` would visit a closed window.

## Linking to items

- The core reads links: `linkParts(in:)` for their parts (UTF-16 ranges) and `Items.linkCandidates` for what they name (`ItemLibrary.linkAnswers(of:in:)`). The app parses no link and folds no name. A backslash is part of a link's text, so pass the page's `raw` on, never what it decoded, and never write an escape backslash. `ItemLinks.spells`, which asks the core, refuses a title that the core and Inkkit would read differently, and `ItemLinks.label` repairs repeated brackets in a label; their doc comments say what. The app never writes such a form.
- Link to Item writes `[[Title]]` only where the core answers `bound` for that title to that item (`LinkAnswer.names`), and otherwise `[[identity|Title]]` (`ItemLibrary.bodyLink(to:in:)`). Never write a link any other way. `LinkAnswer`'s doc comment says why an `unresolved` answer is not enough.
- `ItemRequests` answers the page's `notes` messages. Suggestions are `ItemLinks.Index` matches off the main actor, kept where `LinkAnswer.offers` holds. A link the core does not read as the one link the page posted is answered as not missing with no type, and the item's other links keep their marks. A reply names a link's type (icon from the catalogue, tone from `TypeTone`) only where the core binds it to one item held (`ItemLibrary.linkReadings`). Each icon's image is drawn once (`LinkIcons`) and sent once per reply. Link to Item (`ItemLinkPicker`) answers the page exactly once on every path: chosen, cancelled, the document replaced, the item left, the window gone, or the page's process ended.
- Following a link asks the core what that very link means from its item (`EditorController.openItemLink`) and never guesses by title. Only `bound` opens an item at once; a link the copy has not bound offers the items its name answers to in a menu, and one that names none beeps. No item is made for a link. Wire `onOpenItem` wherever an editor is made. A main window also sets `onFollowItemLink`, which opens a link in the text as Settings > General > Open Items says (`Browser.follow(link:in:order:)`); an editor without it opens the item as `onOpenItem` does.
- A right-click on a link in the text sends `linkMenu`, and `EditorController+LinkMenu` builds the menu from `linkMenuEntries` and carries out the choice: Open and Copy anywhere, and Edit Link (the Format > Link sheet) and Remove Link only on a page that can be edited, for the load the menu was asked on. Remove Link on a link to an item writes its shown words with `unlinkSelected`. Open Link is dimmed unless the page said `openable`.
- `ItemLink.raw` keeps the authored text inside the brackets and defines equality, so `[[Plan]]` and `[[Plan|Plan]]` stay distinct.

## Printing and PDF export

- `PrintDocumentRenderer` renders Inkkit's frozen portable HTML in a separate WebKit view, with images through the checked file path above. It reads pictures from the cache or a saved file only.
- PDF export stops at 200 pages or 64 MB and writes the destination atomically only after rendering succeeds, so a failed export leaves an existing file unchanged.

## Code Review Rules

- **Embed escapes its directory.** Flag any path that reads, serves, or opens an embedded file without `openEmbeddedFile(_:in:)`, follows a symbolic link, or reopens by path. Safe path: use the descriptor `OpenFile` returns.
- **Runnable file opened.** Flag any route that hands a file to another app without `EmbeddedFiles.opens`.
- **Editor made for every view value.** Flag an `EditorController`, a web view, or another costly object made in a view's initializer or given to `State(initialValue:)`. Safe path: `EditorSlot`, or make it in `.task` as Apple's `State` documentation shows.
- **Unguarded private API.** Flag a private WebKit setting set without a `responds(to:)` check, or a new one that Apple's own `WebView` does not use.
- **Link request left open.** Flag a path that ends Link to Item without answering the page once, or that writes a link without `bodyLink(to:in:)`, or parses, escapes or folds a link's text in the app.
- **Edit saved to the wrong place.** Flag a save without the version it was typed on, or one that can land in another item after the page changed items.
